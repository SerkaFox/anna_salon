# WhatsApp: QR и вход по номеру/коду

Развёрнуто 16 сентября 2026 только для BRIMOON. Страница:
https://brimoon.es/whatsapp/connect/main/ — вход по паролю 1234.

## Исправления

- Запрос кода теперь переводит настройку `pairWithPhoneNumber.phoneNumber`
  библиотеки в режим номера. Объект изменяется на месте: его использует ранее
  зарегистрированный callback, поэтому автоматическое обновление QR подавляется
  и после ручного переключения. Наблюдение в исходнике подтвердило прежнее
  рассогласование; его связь со всеми прежними LOGOUT не доказана.
- QR-события больше не перезаписывают статус входа по коду или синхронизации.
- Статус `pairing` явно означает ожидание кода, `authenticated` — синхронизацию,
  `ready` — готовность моста. API и монитор знают новый статус.
- Страница кода опрашивает защищённый endpoint раз в 3 секунды и показывает
  актуальный код при ротации библиотекой (каждые 3 минуты).
- Повторный запрос в пределах срока кода возвращает текущий код, а не обрывает
  попытку новой генерацией. Во время authenticated новая попытка не допускается.
- Убран захардкоженный номер. Начальное значение — ранее известный номер
  соединения или пустое поле; пользователь вводит номер с международным кодом.
- Возврат к QR использует `cancelPairingCode()` и повторное подключение
  обработчиков через `inject()`, без перезапуска браузера или удаления auth.
- При мягком восстановлении браузера выбранный режим номера сохраняется,
  библиотека запускается с нативной настройкой входа по номеру.
- GET состояния браузера ограничен 5 секундами. Новая информация о коде
  защищена паролем, bearer между Django/мостом и запретом кэша.

## Проверки и ограничения

7 тестов Node и 19 тестов Django прошли, Django check без ошибок. Проверки
HTTP страницы пароля, QR, страницы кода и защищённого progress выполнены
без генерации кода и без отправки WhatsApp-сообщений.

Для применения нового server.js перезапущен ТОЛЬКО неподключённый мост
`brimoon-whatsapp-bridge.service`, после двукратной проверки, что он не ready,
не authenticated и не занят генерацией кода. Временный код прежней попытки
после этого недействителен. Gunicorn anna.service обновлён через HUP.
Сохранённая авторизация не удалялась; другие мосты и сервер не перезапускались.
Резерв кода: `backups/dual-login-before-20260916/code.tar.gz`.

Полное прохождение входа по коду до ready требует действий владельца телефона
и пока НЕ подтверждено после исправления. Нельзя считать выдачу кода доказательством
успешной авторизации. Анне следует запросить НОВЫЙ код на обновлённой странице,
ввести его в WhatsApp → Связанные устройства → Привязать устройство →
Связать по номеру телефона. После синхронизации страница покажет Conectado.
