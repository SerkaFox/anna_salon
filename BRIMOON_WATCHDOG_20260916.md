# Монитор BRIMOON — 16 сентября 2026

Установлены отдельные `brimoon-watchdog.service` и `brimoon-watchdog.timer`.
Запуск через 60 секунд после завершения предыдущей проверки, включая после
перезагрузки сервера. Проверки параллельные, таймаут HTTP — 8 секунд.

Проверяются:

- Публичный HTTPS-сайт: HTTP 200 и HTML BRIMOON.
- API `/api/v1/health/` извне и напрямую через Gunicorn: ответ JSON и `SELECT 1`
  к базе данных. Проверка публичная, только GET, без персональных данных;
  ошибка базы возвращает 503 без технических подробностей, кэш запрещён.
- Публичный JSON API обновлений Android.
- WhatsApp: доступность моста, статус основной сессии, при ready — фактический
  CONNECTED через браузер. Ожидание QR считается недоступностью отправки;
  starting/authenticated получают 120 секунд на запуск.
- Службы anna, brimoon-whatsapp-bridge, nginx.
- Диск: менее 2 GB или 5% свободного места; память: менее 300 MB доступно;
  наличие сетевого carrier у eno1. Краткие обрывы между проверками не гарантированно
  обнаруживаются; CPU и полные журналы приложений этот монитор не анализирует.

Telegram использует существующего «Пушика», его `TG_BOT_TOKEN` и первый чат
из `bridge_state.json`, как существующий серверный `notify_failure.sh`.
Секреты не копировались в Git или новые настройки.

Ошибка подтверждается двумя неудачными проверками подряд. После успешной
доставки повторяется не чаще раза в час. Восстановление отправляется отдельно.
При ошибке отправки Telegram попытка повторяется на следующей проверке;
краткий сбой, исчезнувший до доставки, не сохраняется в очереди.
Состояние хранится приватно в `logs/brimoon_watchdog.json`; блокировка файла
предотвращает одновременные запуски. Падение самого watchdog вызывает существующий
Telegram `sergey-service-alert@` через systemd OnFailure.

Проверено: 3 теста API, 5 тестов логики уведомлений, Django check, реальная
доставка теста и предупреждения WhatsApp в Telegram. При первоначальном запуске
Cloudflare отказал стандартному Python User-Agent: отправились предупреждения;
после настройки явного User-Agent отправились восстановления. Финальная проверка:
сайт, API, БД, обновления, службы, ресурсы — OK; WhatsApp — ожидает QR.

WhatsApp не перезапускался, авторизация не удалялась. Другие мосты и общий
server-watcher не изменялись. Gunicorn BRIMOON мягко перечитал код через HUP.
Резерв исходного urls.py: `backups/watchdog-before-20260916/urls.py` на сервере.

Диагностика:

```sh
systemctl list-timers brimoon-watchdog.timer
journalctl -u brimoon-watchdog.service -n 50 --no-pager
python3 /home/seradmin/anna/deploy/brimoon_watchdog.py --test
```

Важно: локальный монитор не может отправить сообщение при полном отключении
сервера, интернета или Telegram. Для таких событий нужен независимый монитор
на другом устройстве/сервере; в этой задаче он не установлен.
